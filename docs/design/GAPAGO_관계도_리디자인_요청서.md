# GAPAGO 관계도 (Papers → Limitations → GAPs) 리디자인 요청서

## 1. 현재 상태 및 문제점

현재 관계도는 Papers → Limitations → GAPs 간의 연결 관계를 하나의 통합 그래프로 시각화하고 있으나, 다음과 같은 문제가 있음:

### 핵심 문제
- **텍스트 truncation**: 노드 내 텍스트가 `...`으로 잘려 내용 파악 불가
- **연결 관계 비가독성**: 엣지가 가늘고 연해서 어떤 Paper에서 어떤 Limitation이 나왔고, 어떤 GAP으로 수렴하는지 추적 불가
- **노드 타입 구분 부족**: Paper, Limitation, GAP 노드의 시각적 차별화가 약함 (형태 차이만 미미하게 존재)
- **축소 상태에서 정보 전달력 제로**: 전체 구조를 한눈에 보려고 축소하면 모든 텍스트가 읽히지 않음
- **전체 구조 패턴 미파악**: 어떤 GAP이 여러 limitation에서 수렴하는 중요한 것인지, 어떤 Paper가 많은 limitation을 가지는지 등의 패턴이 시각적으로 드러나지 않음

### 유지해야 할 기존 요구사항
- **섹션 분리 금지**: 3개의 column으로 나누지 않고 하나의 통합 그래프로 시각화
- **전체 연결 관계 우선 제시**: 처음에 전체적인 연결 구조가 한눈에 보여야 함
- **확대하여 상세 확인 가능**: 사용자가 zoom-in하여 개별 노드의 상세 내용 확인 가능
- **추가적인 시각적 효과 허용**

---

## 2. 리디자인 목표

> **"축소 상태에서 전체 연결 구조의 패턴이 읽히고, 확대하면 개별 내용이 보이는 그래프"**

---

## 3. 상세 구현 요구사항

### 3.1 Semantic Zoom (줌 레벨별 정보 계층)

가장 핵심적인 개선 사항. 줌 레벨에 따라 노드의 표현 방식이 달라져야 함.

**축소 상태 (Overview)**:
- 노드를 **컬러 dot + 짧은 라벨(1~2 키워드)**로 표시
- 텍스트를 억지로 넣지 않음 → `...` 문제 원천 해결
- 연결선의 **흐름 패턴과 클러스터 구조**가 시각적 주인공
- 어떤 GAP에 여러 경로가 수렴하는지, 어떤 Paper가 많은 limitation을 갖는지가 바로 보여야 함

**확대 상태 (Detail)**:
- 노드가 **카드 형태로 확장**되면서 전체 텍스트 표시
- 카드 내부에 타입 라벨 (Paper / Limitation / GAP) 포함
- 필요 시 카드 내에 메타 정보 (연결된 노드 수 등) 표시

**전환**:
- 줌 레벨에 따라 부드럽게 전환 (dot → 카드 애니메이션)
- 임계값 기반으로 2단계 또는 3단계 전환

### 3.2 노드 디자인

**타입별 시각 차별화** (축소 상태에서도 색상만으로 타입 구분 가능해야 함):

| 타입 | 색상 계열 | 스타일 | 비고 |
|------|----------|--------|------|
| **Paper** | Indigo/Blue 계열 | Filled 배경 + 흰 글씨 | 출발점으로서 안정적 느낌 |
| **Limitation** | Amber/Warm 계열 | 연한 배경 + bordered | 중간 단계, 주의를 끄는 톤 |
| **GAP** | Coral/Red 계열 | 강조 bordered, 테두리 두껍게 | 최종 도출 결과물로서 눈에 띄어야 함 |

**GAP 노드 크기 가변**:
- 연결된 Limitation 엣지 수에 비례하여 노드 크기 증가
- 여러 limitation에서 수렴하는 중요한 GAP일수록 시각적으로 크고 도드라지게

### 3.3 엣지(연결선) 디자인

**2단계 구분**:
- Paper → Limitation 엣지: 한 가지 스타일 (예: 실선)
- Limitation → GAP 엣지: 다른 스타일 (예: 파선 또는 다른 색상)

**시각적 처리**:
- **Bezier curve** 사용 (직선 대신 곡선) → 경로 추적이 쉽고 겹칠 때 덜 혼잡
- 엣지에 **그라데이션** 적용 (출발 노드 색 → 도착 노드 색) → 방향성 자연스럽게 전달
- 화살표(arrowhead) 명확하게 표시
- 기본 상태에서 엣지 opacity를 약간 낮춰서 노드가 우선 읽히게 하되, 흐름은 인지되도록

### 3.4 인터랙션

**Hover 시 경로 하이라이트** (필수):
- 노드 hover 시 해당 노드와 **직접 연결된 모든 경로(노드+엣지)만 하이라이트**
- 나머지 노드/엣지는 opacity 0.1~0.15로 fade-out
- 이것이 없으면 노드 10개 이상에서 연결 관계 추적 불가능

**클릭 시 상세 패널** (권장):
- 노드 클릭 시 사이드 패널 또는 팝오버에 전체 텍스트, 연결된 노드 목록 표시
- 해당 노드의 upstream/downstream 경로를 텍스트 리스트로도 확인 가능

**Zoom & Pan**:
- 마우스 휠 줌, 드래그 팬 지원
- 줌 레벨에 따른 Semantic Zoom 전환 (3.1 참고)
- 더블클릭 시 해당 노드 중심으로 줌인

### 3.5 레이아웃

**방향성 있는 자유 배치**:
- 엄격한 column 분리는 하지 않되, **왼→오 방향으로 약한 directional force** 적용
- Paper 노드가 자연스럽게 왼쪽, GAP 노드가 오른쪽에 위치하되, 기계적 정렬은 아닌 유기적 배치
- 연결이 많은 노드끼리 자연스럽게 클러스터링

**레이아웃 알고리즘 선택지** (현재 스택에 맞게 선택):
- Dagre (계층형) + 약간의 유연성 부여
- Force-directed + directional bias (x축 방향으로 Paper < Limitation < GAP 순서 유도)
- 어느 쪽이든, 최종 결과에서 **전체 흐름 방향(좌→우)이 자연스럽게 읽혀야 함**

## 4. 시각적 분위기 참고

- 전체적으로 **밝고 깔끔한 톤** (현재 GAPAGO 프론트엔드 디자인 기조와 일관)
- 배경은 흰색 또는 매우 연한 gray
- 노드 간 여백 충분히 확보
- 과도한 장식 없이, **색상과 크기와 인터랙션**으로 정보 전달

---

## 5. 구현 우선순위

아래 순서대로 구현. 1~3이 핵심이며, 4~5는 추가 개선.

1. **Semantic Zoom**: 축소=컬러 dot+키워드, 확대=카드 전체 텍스트
2. **노드 색상/크기 차별화**: 타입별 색상, GAP 크기 가변
3. **Hover 시 경로 하이라이트 + fade-out**
4. **엣지 스타일링**: bezier curve, 그라데이션, 2단계 구분
5. **클릭 시 상세 패널**

---

## 6. 기술 참고사항

- 현재 GAPAGO 프론트엔드 스택에 맞춰 구현할 것
- 그래프 라이브러리가 이미 사용 중이라면 해당 라이브러리 내에서 구현
- 새로 도입이 필요하다면 React Flow, D3.js, Cytoscape.js 등 검토 가능
- 성능: 노드 30~50개 수준에서 부드러운 줌/팬/인터랙션 보장
