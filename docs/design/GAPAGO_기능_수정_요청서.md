# GAPAGO 기능 수정 요청서 (Feature Branch)

> **브랜치**: 기능(feature) 전용  
> **범위**: 백엔드 로직, 파이프라인 동작, 데이터 흐름 관련 수정  
> **주의**: 웹 UI 변경은 별도 웹 브랜치에서 처리. 이 문서에는 포함하지 않음.

---

## 수정사항 목록

### 1. 한계점 미추출 논문 — 원인 분석 및 해결

**현재 상태**:
- 일부 논문에서 한계점(Limitation)이 추출되지 않고 빈 결과가 반환됨

**요청 사항**:

**(a) 원인 분석 리포트 작성** (수정 전 먼저 수행):
- 한계점이 추출되지 않은 논문 목록을 식별
- 논문별로 실패 원인을 분류하여 리포트 작성. 가능한 원인 후보:
  - 논문 전문(full-text) 가져오기 실패 (ArxivLoader 에러, PDF 파싱 실패 등)
  - 전문은 가져왔으나 한계점 추출 프롬프트에서 빈 응답 반환
  - 논문 텍스트 길이가 context window를 초과하여 truncation 발생
  - 2-track 추출 (Track 1: 저자 명시 / Track 2: 구조적/암시적) 중 특정 track에서 실패
  - 기타 예외 처리 누락
- 리포트 형식: 각 실패 케이스별 원인, 해당 논문 예시, 에러 로그(있다면) 포함

**(b) 해결책 실행**:
- 리포트 기반으로 해결책 수립 후 실행
- 해결 시 고려사항:
  - 전문 가져오기 실패 시 → 재시도 로직 또는 fallback (abstract 기반 추출 등)
  - 빈 응답 시 → 프롬프트 개선 또는 retry with different prompt
  - Truncation 시 → 청킹 전략 또는 관련 섹션 선별 추출
- 수정 후, 기존 실패 논문들에 대해 한계점이 정상 추출되는지 검증

---

### 2. 웹 검색 결과 활용 현황 리포트 및 개선 제안

**현재 상태**:
- Tavily 등을 통한 웹 검색 기능이 파이프라인에 존재하나, 실제로 어떻게 활용되고 있는지 불명확

**요청 사항**:

**(a) 현황 리포트 작성**:
- 웹 검색이 파이프라인 내 어느 단계에서 호출되는지 정리
- 검색 쿼리가 어떻게 생성되는지 (논문 키워드 기반? 사용자 입력 기반?)
- 검색 결과가 이후 어떤 노드/프로세스에 전달되는지
- 실제 분석 결과(한계점 추출, GAP 도출)에 검색 결과가 반영되고 있는지, 반영된다면 어떤 방식으로
- 검색 결과가 사용되지 않고 버려지는 경우가 있는지

**(b) 추가 활용 방안 제안**:
- 현황 리포트 기반으로, 웹 검색 결과를 더 효과적으로 활용할 수 있는 방안 제안
- 예시 (참고용, 실제 파이프라인 분석 후 구체화):
  - GAP 도출 시 최신 연구 동향과의 cross-reference
  - 추출된 한계점이 이미 해결된 것인지 웹 검색으로 검증
  - 관련 데이터셋/벤치마크 정보 보강
- 제안은 구현 난이도와 기대 효과를 함께 명시

---

### 3. 논문 선택 개수 동적 K 반영 확인

**현재 상태**:
- 논문 선택 개수(K)가 동적으로 결정되도록 구현되었으나, 정상 반영 여부 미확인

**요청 사항**:
- 다양한 쿼리/조건에서 K 값이 의도대로 동적으로 결정되는지 검증
- 확인 항목:
  - K 값 결정 로직이 어떤 기준으로 동작하는지 (검색 결과 수, 관련도 점수 등)
  - 실제 실행 시 K 값이 쿼리별로 다르게 설정되는지
  - K 값이 프론트엔드에 정확히 전달되어 `k/n` 표시에 반영되는지
  - Edge case: 검색 결과가 매우 적을 때(1~2편), 매우 많을 때(20편+)의 K 동작
- 결과를 간단히 리포트하고, 문제가 있으면 수정

---

## 작업 순서 권장

1. **#3 동적 K 확인** — 검증 위주, 문제 없으면 빠르게 완료
2. **#2 웹 검색 현황 리포트** — 코드 분석 + 리포트 작성 (수정은 제안까지만)
3. **#1 한계점 미추출 원인 분석** — 리포트 먼저 → 확인 후 해결책 실행

> **#1은 리포트 작성 후 일단 멈추고, 리포트 내용을 확인한 뒤 해결책 실행을 지시할 것.**  
> (원인에 따라 해결 방향이 달라질 수 있으므로)
